# Activity-Relay v3.1.0-rc4

- Application version: `3.1.0-rc4`
- Debian package version: `3.1.0~rc4-1`

## Directory Protocol v3

RC4 introduces Directory Protocol v3 for descriptive participating-site
telemetry. A v3 register or heartbeat may include
`participating_instance_count`, derived from `connected_instances.count` in the
relay's own `/status.json`. The telemetry is bounded and optional; failure to
read it never changes relay delivery or follow behavior.

Protocol v2 remains the profile synchronization contract. V2 registration sends
the complete normalized profile, while v2 heartbeat and unregister are
identity-only. The client selects v3 only when the Directory explicitly
advertises it in schema-4 status capabilities, and otherwise retains v2/v1
compatibility.

Scheduler state now accepts persisted profile protocol version 3. When a
negotiated v2/v3 heartbeat reports a different protocol version than the one
that last carried the stored profile digest, AR performs one registration to
reconcile the profile under the newly negotiated protocol.

The API/server scheduler now performs one immediate reconciliation with every
enabled Directory when the server process starts. A registered relay with an
unchanged profile sends a heartbeat; a new or profile-changed relay registers.
Persisted retry, rate-limit, authentication, suspension, enrollment, lifecycle,
and malformed-response deadlines are not bypassed by the startup pulse.

Manual `directory register`, `directory heartbeat`, and `directory sync`
commands now coordinate through the scheduler's Redis lease when file-backed
scheduling is enabled. Successful manual operations advance the scheduler's
persisted success/next-heartbeat state, and register/sync also persist the
profile digest and negotiated profile protocol.

## Static-site operator changes

`participation_url` remains part of the profile sent to Directories but is no
longer displayed by the relay's local static landing page. The container image
now includes `activity-relay-rebuild-site`, including `--relay-config`, so the
same rebuild interface is available in package and container deployments.

Top-level YAML keys such as `DIRECTORY_PROFILE` and `SUPPORT` must begin at
column 1. Their child values remain indented beneath the key.

## Documentation layout

The project README is intentionally concise again. Installation is documented
in `docs/INSTALLATION.md`, day-to-day operation and CLI examples in
`docs/ADMINISTRATION.md`, and contributor/test procedures in
`docs/DEVELOPMENT.md`.

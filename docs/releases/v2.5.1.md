# Activity-Relay v2.5.1

> [!IMPORTANT]
> Activity-Relay v2.5.1 is a security and reliability patch for the stable
> v2.5 line. Operators running v2.5.0 should upgrade, especially when their
> relay has follower-style relationships with another relay.

## Summary

A real-process FEP-ae0c test demonstrated that two mutually connected v2.5.0
relays could repeatedly exchange valid, relay-authored `Announce` activities
for one canonical source activity. Each hop minted a new wrapper ID, so
ordinary activity-ID deduplication did not stop the cycle.

v2.5.1 makes relay-reflection prevention a non-configurable protocol safety
invariant.

## Fixes

- Exclude the relay that supplied a referenced `Announce` from the new fan-out.
- Exclude the canonical activity's origin domain from that fan-out.
- Atomically reserve the fetched canonical activity ID before minting another
  relay wrapper.
- Store only a SHA-256-derived Redis marker key, not the raw actor, object,
  inbox, or activity URL.
- Acknowledge duplicate canonical references without creating another
  relay-authored activity.
- Release the reservation after known queue-admission failures.
- Retain the marker for the same bounded fifteen-minute horizon used by shared
  relay payloads.

## Validation

The release baseline passed:

- focused canonical loop-guard and referenced-Announce tests;
- complete serialized Redis-backed tests;
- complete serialized race tests;
- `go vet`;
- website and operations Python suites;
- Caddy example validation;
- missing, directory-valued, and valid Compose actor-key preflight cases;
- local release-container build and version inspection;
- native `2.5.1-1` Debian package build and Lintian;
- package metadata, contents, and embedded binary-version inspection; and
- the required two-server/two-worker/two-Redis process invariant.

The process invariant requires:

- `classification: no_reflection_observed`;
- zero generated cross-relay responses after the seed activity;
- valid signed actor and canonical-object fetches;
- at least one retained canonical loop marker; and
- no final ready, delayed, claimed, retry, or retained-activity backlog.

## Compatibility

No actor-key rotation, endpoint change, configuration rename, task-format
migration, or Redis data conversion is required.

The new canonical marker is temporary internal safety state. Existing
subscriptions, followers, publishers, queued work, delivery health, website
content, and operator configuration remain compatible.

## Scope

This patch does not add RFC 9421 HTTP Message Signatures, RFC 9530
`Content-Digest`, stale-receiver cleanup, or alternative durable backends.
Those remain separate post-v2.5.1 work.

## Upgrade

Container deployments should use:

```text
ghcr.io/thystra/activity-relay:2.5.1
```

Native deployments should install:

```text
activity-relay_2.5.1-1_amd64.deb
```

Back up the existing actor key and Redis data according to the normal upgrade
procedure. The package preserves both during the tested upgrade path.

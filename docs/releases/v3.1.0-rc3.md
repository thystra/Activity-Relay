# Activity-Relay v3.1.0-rc3

- Application version: `3.1.0-rc3`
- Debian version: `3.1.0~rc3-1`

RC3 is a protocol-boundary and operator-safety candidate. It retains the RC2
public-profile/support presentation while hardening Directory integration and
adding bounded receiving-site telemetry.

## Changes

- Protocol v2 register and heartbeat may report the deduplicated number of
  receiving sites. Telemetry is optional and does not affect relay delivery.
- `DIRECTORY_PROFILE.participation_mode` is controlled to `open`, `restricted`,
  or `closed`. Invalid optional profile fields are warned about, omitted, and are
  never transmitted to a Directory.
- `relay -t` / `relay --test-config` reports configuration problems without
  Directory/Redis network requests or state mutation; `--strict` makes optional
  metadata warnings fail the check.
- The Directory HTTP client refuses redirects, bounds bodies and headers,
  disables response compression and environment proxies, uses bounded
  connection/TLS/header/overall timeouts, requires TLS 1.2+, rejects dangerous
  loopback/link-local/multicast destinations, and validates remote status tokens
  before terminal output. RFC1918/private addresses remain permitted for
  intentionally configured split-DNS/private Directory deployments.
- One Directory reconciliation has a total time budget so a hostile or broken
  Directory cannot indefinitely occupy the scheduler. Directory failures remain
  isolated from ActivityPub serving and fan-out.

## RC gate

Deploy the matching ARD `1.3.0-rc3` candidate first. Confirm status negotiation,
register, heartbeat telemetry, profile omission warnings, malicious-response
containment, and continued ActivityPub health before promotion.
